# Ambiens

Static React app: tap water potability per commune (SISE-Eaux checks) + drought,
river and groundwater context. GitHub Pages under `/ambiens/`.

## Commands

- bun everywhere. Tests: `bun run test:ci` (Vitest) — never `bun test`.
- Single file: `bun run test:ci src/lib/regles.test.ts`.
- Dev: `bun run dev` (5173); local prod: `bun run build && bun run preview`
  (4173) — both serve under `/ambiens/`.
- Gate before any delivery: `bun run typecheck && bun run lint && bun run format:check && bun run test:ci`.
- Every version is pinned exact — deps, actions (full SHA), runner image, Bun
  (`packageManager`). Add a dep with `bun add --exact`: plain `bun add` writes a
  `^` range. Bumps come from Dependabot, not by hand.

## Architecture

- Flow: `App.tsx` holds the `insee` state (kept in sync with `?commune=` by
  `lib/url.ts`) → `api/queries.ts` (one `queryOptions` factory per source:
  queryKey/staleTime/retry/timeout, `skipToken` when no commune is set) →
  `api/*.ts` (bare fetch + one Zod schema per endpoint) → rendering per feature.
- Verdict = atomic aggregation: a single `['qualite', insee]` query whose
  queryFn chains `fetchReseaux` → `parLots(8)` → `lib/regles.ts` (official ARS
  cascade first, recomputation as fallback, disagreement reported; commune
  verdict = worst network verdict).
- Each context panel (VigiEau, hydro, piezo) carries its own query, wrapped in
  `components/EtatSection`: one failed source blocks neither the verdict nor the
  other panels.
- Layers: `lib/` pure, no network; `api/` network + validation; `features/` UI
  composition; `components/ui/` generated by shadcn.

## Cross-cutting constraints

- Hub'Eau: bare `fetch(url)`, no custom header (the WAF blocks the OPTIONS
  preflight). HTTP 206 = success.
- `src/components/ui/**` and `components.json`: generated by the shadcn CLI,
  never edited by hand (details in the ui rule).
- `src/lib/regles.ts`: 1:1 port of the engine from the original prototype,
  locked down by tests — do not "improve" the verdict cascade.

rule stale, fix the doc in the same commit; when a new convention crystallizes,
add a rule. They guide upfront — never let them re-explain code that should
